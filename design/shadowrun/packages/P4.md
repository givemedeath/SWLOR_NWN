# P4 — Convert item-property display names in the TLK

**Tier:** Mid      **Wave:** 1 (deferred)      **Model:** sonnet
**Task ID:** 7 *(controller-managed; you cannot and should not touch the task list)*

## Owned files

- `SWLOR_Haks/sw_tlk/sw_tlk.tlk.json` — the only file you edit
- `SWLOR_Haks/sw_tlk/sw_tlk.tlk` — regenerated from the JSON, never hand-edited

**Nothing else.** No `.2da` changes are needed and none are permitted. No C#. If you notice a problem
elsewhere, report it in your final message rather than fixing it.

## Context

Item descriptions build their text from TLK strings resolved through the item-property tables
(`Item.BuildSingleItemPropertyString`, `SWLOR.Game.Server/Service/Item.cs:1117`). The property's
displayed name comes from `itempropdef.2da`'s **`GameStrRef`** column — not `Name` — and its subtype
and cost-table values resolve through further `iprp_*` tables.

The scoping pass established the key fact that makes this safe: **50 of the 89 item-property types
SWLOR actually uses already point at custom TLK entries** (`strref >= 16777216`). So this is a pure
text edit. You do **not** need to repoint any strref, add any entry, or renumber anything — which is
the operation that would otherwise risk breaking every item description in the game.

The 57 candidate entries are listed in `_p4_targets.md` beside this brief. They were found by
collecting every custom strref referenced from `itempropdef.2da`, `itemprops.2da`, and every `iprp_*`
table, then filtering for combat vocabulary.

Waves 0–1 already converted the character sheet and HUD. This package brings item descriptions into
line with the vocabulary those established (decisions D4–D6 in `DECISIONS.md`).

## Requirements

1. Apply this vocabulary, which matches what already ships on the character sheet:

   | Current | Becomes |
   |---|---|
   | `Defense` (the bare physical defense stat) | `Armor` |
   | `Defense - Physical` | `Armor` |
   | `Defense - Force` | `Spell Defense` |
   | `Force Defense Up` / `Force Defense Down` | `Spell Defense Up` / `Spell Defense Down` |
   | `Evasion` | `Defense Pool` |
   | `DMG` | `DV` |
   | `HP` | `Physical` |
   | `FP` | `Magic` |
   | `Stamina` / `STM` | `Stun` |
   | `Force Attack` | `Spellcasting` |

2. **Preserve the exact punctuation and trailing whitespace of every entry.** Several are formatting
   fragments — `"HP:"`, `"Force Attack: "` (note the trailing space), `"Requires Skill: "` — and the
   description builder concatenates them directly. `"FP:"` becomes `"Magic:"`, and
   `"Force Attack: "` becomes `"Spellcasting: "` with its trailing space intact. Dropping a colon or a
   space corrupts every description that uses it.

3. Apply the rule to compound forms consistently: `HP Up` → `Physical Up`, `FP Regen` → `Magic Regen`,
   `STM Regen` → `Stun Regen`, `NPC HP` → `NPC Physical`, and the three tooltip sentences
   (`"Increases the amount of HP granted when this item is equipped."` and its FP and stamina
   siblings).

4. **Do not rename ability or perk proper nouns.** These contain the word "Defense" or "Evasion" but
   are names, not stat labels, and renaming them produces nonsense like "Crippling Armor":

   `Crippling Defense`, `Flowing Defense`, `Overwhelming Defense`, `Absolute Defense`,
   `Evasion Purity`, `Physical Defense Purity`, `Force Defense Purity`

   Ability naming belongs to P8. Leave all seven exactly as they are.

5. **Do not rename typed elemental resistances.** `Electrical Defense Up/Down`, `Mind Defense Up/Down`,
   `Light Defense Up/Down`, `Dark Defense Up/Down`, `Thermal Defense`, `Explosive Defense`,
   `EM Defense`. These are damage-type resistances rather than the armor stat; Shadowrun has no
   elemental armor, and "Thermal Armor" would misdescribe them. Only the *bare* `Defense` stat and the
   explicitly Physical/Force ones change.

6. Change **only** the `text` field of the targeted entries. Do not add, remove, reorder or renumber
   entries, and do not touch any entry's `id`. The file must keep exactly 22,284 entries.

7. Leave `Attack` and `Delay` alone. P5 owns the damage and initiative side in Wave 2 and will rename
   them together; renaming here would diverge from the character sheet until then.

## Project rules that apply

From `AGENTS.md`, quoted because these are the ones this package can violate:

> "New custom TLK strings must use a pre-existing empty TLK slot or gap before appending new IDs at
> the end of `SWLOR_Haks/sw_tlk/sw_tlk.tlk.json`."

> "NWN custom TLK references in 2DA files use `16777216 + tlkId`. When moving or adding a TLK entry,
> update every 2DA/reference to the matching custom strref."

> "After editing `sw_tlk.tlk.json`, regenerate `sw_tlk.tlk` before building or handing off the change."

The first two are satisfied trivially **provided you only edit existing `text` fields** — no new IDs,
no moves, so no 2DA reference can go stale. If you find yourself wanting to add an entry, stop and
report it instead.
